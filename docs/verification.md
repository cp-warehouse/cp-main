# 초기 DB 환경 · 실행 검증

검증일: 2026-09-30. 대상: 초기 4개 테이블과 Docker 실행·보존·복구 흐름.

## 환경과 재현

- 로컬 macOS / Docker Linux arm64
- Docker Engine 29.4.1
- PostgreSQL 18.6, Debian Bookworm
- 이미지: `postgres:18-bookworm@sha256:3725f4e2499eef5134592b3b4ab79a543ed7f8e533b05b5b637af926630f6650`
- 명령: 저장소 루트에서 `python3 scripts/verify_postgres.py`

## 확인 결과

| 항목 | 검증 방식 | 결과 |
|---|---|---|
| 최초 생성 | 새 외부 볼륨에서 실행 후 public 테이블 목록 확인 | 4개 생성 |
| 외부 식별자 중복 | 같은 namespace·external_value 재입력 | 고유 제약으로 거부 |
| 기업 연결 | 존재하지 않는 company_id로 제품 입력 | FK로 거부 |
| 재무 재처리 | 같은 출처·개정·항목·추출 버전 재입력 | 고유 제약으로 거부 |
| 재무 정정 | 같은 계정에 서로 다른 개정 2개 입력 | 이전 값 100·정정 값 110 동시 보존 |
| 입력 기준 | 역전된 기간·잘못된 통화 형식·연결 기준 입력 | CHECK 제약으로 거부 |
| 중지 후 시작 | 중지·기동 전후 4개 테이블의 전체 행·필드 비교 | 일치 |
| 컨테이너 재생성 | down/up 후 컨테이너 ID 변경과 전체 데이터 비교 | 새 컨테이너·데이터 일치 |
| 백업 복구 | pg_dump → 별도 restore_check DB → 전체 데이터 비교 | 일치 |

합성 테스트 데이터만 사용. 검증용 컨테이너·네트워크·볼륨은 실행 종료 시 제거. 일반 개발 볼륨과 분리된 고유 이름 사용.

## 확인하지 않은 범위

- 실제 외부 API·HTML·PDF 데이터의 적재 성공 여부
- 동료의 컴퓨터·다른 CPU 아키텍처에서의 실행
- 실서비스 부하·대용량 백업·재해 복구·OS 재부팅
- 최신 유효 재무 값 선택, 원문 변경 자동 감지, 감사 로그
- 일반 사용자 계정의 비밀번호 인증·최소 권한 정책

노션 원문은 권한이 필요할 수 있는 팀 기록. 저장소의 설계 요약과 실행 설명은 공개 GitHub에서 열람 가능.
